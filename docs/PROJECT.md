## 1. 문제 정의와 핵심 가치

선거 기간에 쏟아지는 공약이 실제로 이행되는지 확인하기 어렵다. 공약 목록은 선관위가 공개하지만, 이행 현황은 243개 지자체 사이트에 제각각의 형식(HTML 표, PDF, HWP, 게시판)으로 흩어져 있어 통합 조회가 불가능하다.

**핵심 가치 3가지**

1. **통합 조회** — 전국 공약 데이터 + 지역별 이행 추적을 한 곳에서
2. **검증 가능한 AI 판정** — 모든 판정에 근거 문단·원문 링크·수집 시점을 연결
3. **불일치 탐지** — 지자체 자가보고("이행완료")와 실제 근거 사이의 괴리를 표시

**차별점**: 공약 목록 서비스(선관위 정책공약마당)는 이미 존재. 이행 현황의 자동 수집·판정·통합 조회가 이 프로젝트의 고유 영역.

## 3. 기능 명세 (MVP)

### 3.1 데이터 수집

- **선관위 API 수집기**: 선거공약 정보 API + 당선인정보 API(WinnerInfoInqireService2). 민선8기 sgId=20220601, 민선9기 sgId=20260603. 수집 후 자체 DB 적재(API 트래픽 1만 건/일 제한은 1회 적재 방식으로 무관)
- **지자체 크롤러(어댑터 패턴)**: 공통 인터페이스 fetch → parse → normalize + 지자체별 설정(URL, 셀렉터, 문서 형식, 상태값 매핑). MVP 어댑터 2개: 경기도(공약실천계획서 + 분기별 추진현황), 서울시(시장 공약 추진현황 — 페이지 구조 사전 조사 필요)
- **스냅샷 시계열**: 분기별 추진현황을 task_snapshots에 누적. diff 감지로 변경분만 재처리(LLM 비용 절감 + 상태 변화 이력 자체가 콘텐츠)

### 3.2 처리 파이프라인

- **파싱·정규화**: HTML(BeautifulSoup), PDF(pymupdf), HWP(hwp5txt). 상태값은 원본 보존 + 매니페스토 표준 5분류(완료/이행후계속추진/정상추진/일부추진/보류·폐기) 매핑 테이블
- **공약↔과제 매칭(2단계)**: ① 임베딩 코사인 유사도로 공약별 top-5 후보 추출 → ② LLM이 이행 수단인 과제 확정(복수 선택 또는 NONE). NONE = 실천계획 누락 공약 → 별도 표시(킬러 콘텐츠)
- **LLM 이행 판정**: Batch API(3사 모두 50% 할인), 구조화 출력 `{verdict, confidence, rationale, evidence[], self_reported_status, discrepancy}`. 판정 모듈은 모델 불가지론 인터페이스(`judge(pledge, evidence) → JudgmentSchema`, LiteLLM 또는 자체 어댑터)로 구현하고 모델명은 설정값. 기본값 Gemini 2.5 Flash 1차 전수 → confidence 낮거나 discrepancy 건만 상위 티어 재판정(캐스케이드). 최종 모델은 4주차 골든셋 베이크오프로 선정. 시스템 프롬프트 캐싱 적용. **판정·매칭 입력은 인물명·정당명 마스킹(블라인딩 — 10장 중립성 정책)**
- **교차검증**: 매니페스토실천본부 연례 평가(연 1회) — 발표 PDF를 사람이 수동 확보 → LLM 구조화 추출(`{region, year, grade, scores}`, 판정 파이프라인 부품 재활용) → 243행 검수 후 적재. 원천 사이트는 봇 차단이라 직접 크롤링 제외. 발표 뉴스 감지·채점식 자체 재현은 Phase 2

### 3.3 웹 서비스 (Nuxt 3 반응형)

- **홈**: 지역 선택(지도 또는 목록) + 전국 요약 통계
- **지역 대시보드**: 단체장 공약 목록, 분야별 필터, 이행률 집계(자가보고 기준 / AI 판정 기준 병기)
- **공약 상세**: AI 판정 + 근거 문단 발췌 + 원문 링크 + 수집 시점, 지자체 자체평가와 나란히 비교, discrepancy 강조, 상태 변화 타임라인
- **방법론 페이지**: 데이터 출처, 판정 기준, 한계 명시 (신뢰성의 핵심 — 반드시 포함)
- 조회 페이지는 Nitro route rules 기반 ISR 캐싱(트래픽 스파이크 방어 + 함수 호출 최소화)

### 3.4 사용자 Q&A — 하이브리드 RAG (MVP 포함)

- **쿼리 라우터**: 초저가 티어 LLM(Gemini 2.5 Flash-Lite급, 질의당 0.01원 미만)이 질의에서 구조화 필터 추출 `{region, person, field, status, free_text}` → 필터만으로 답 가능한 질의("서울시장 교통 공약 중 진행 중인 것")는 **SQL 조회 결과를 카드로 직접 렌더**(LLM 답변 생성 생략 = 비용 0에 수렴) → free_text가 있는 질의("GTX 어디까지 진행됐어?")만 벡터 검색 + 근거 인용 답변 생성(기본값: 판정 1차와 동일 모델로 통일 — 프롬프트·용어 관리 일원화)
- **출처 의무**: 모든 답변에 공약 상세 페이지 링크 포함. 근거 없는 단정 금지를 프롬프트 + 출력 검증으로 강제
- **비용·어뷰징 방어** (LLM이 요청 경로에 들어가는 유일한 지점):
  - 정규화 질의 캐싱(동일 질문 재사용)
  - IP/세션 rate limit (Upstash Redis 무료 티어 또는 Supabase 테이블 기반)
  - Nitro server/api 스트리밍 응답(Vercel 함수 시간 제한 대응). 한도 초과 시 Q&A만 로그인 뒤로 이동하는 단계적 방어
- **범위 제한**: 공약 데이터 관련 질의만 응답, 그 외는 정중히 거절(프롬프트 가드). 평가·의견 유도 질문("○○시장 잘한 거야?")은 데이터 전달로 한정하고 정치적 논평 거절 — 중립성 방어의 핵심

### 3.5 운영·배치

- GitHub Actions 스케줄 워크플로: 분기 크롤링·재판정 배치 + 주 1회 Supabase 유휴 방지 핑
- 크롤러 실패 시 Discord/Slack webhook 알림 (조용한 실패 금지)
- 골든셋 회귀 테스트: 판정용 수작업 라벨 30~40건 + Q&A용 질의 20건(SQL형 5 · 시맨틱형 5 · 범위 외 5 · 유도성 정치 질문 5)으로 매칭 정확도·판정 일치율·답변 근거충실성·거절 일관성을 배치마다 측정
- **국내 IP 이슈 대응**: 공공 사이트가 GitHub Actions(해외 IP)를 차단하면 self-hosted runner(집 PC) 또는 국내 무료 VM으로 해당 크롤러만 분리

## 7. DB 스키마 개요

```text
-- 기준 데이터
winners          (winner_id, sg_id, sg_type, region, party, name, ...)
pledges          (pledge_id, winner_id, title, content, field, source, term)
-- 이행 데이터
tasks            (task_id, adapter_id, name, dept, budget, raw_status, source_url, fetched_at)
task_snapshots   (snapshot_id, task_id, period, raw_status, normalized_status, progress_text)
status_mapping   (adapter_id, raw_status, normalized_status)   -- 매니페스토 5분류
-- AI 산출물
matches          (pledge_id, task_id, similarity, method, confirmed)
judgments        (judgment_id, pledge_id, verdict, confidence, rationale, model, judged_at)
evidence_chunks  (chunk_id, task_id, text, embedding vector, source_url, page, fetched_at)
-- 교차검증
manifesto_grades (region, year, grade, scores, source_doc, verified_at)   -- LLM 추출 후 검수 완료분만
-- Q&A
qa_cache         (query_hash, normalized_query, response, created_at, hit_count)
rate_limits      (key, window_start, count)   -- Upstash 사용 시 생략
-- 운영
adapters         (adapter_id, region, base_url, parser_type, enabled, last_success_at)
golden_set       (pledge_id, human_match_task_ids, human_verdict, labeled_at)
qa_golden_set    (query, query_type, expected_behavior, labeled_at)   -- sql/semantic/out_of_scope/political
```

원칙: 원본값(raw)과 정규화값 분리 저장. 스냅샷은 덮어쓰지 않고 누적. 판정은 모델·시점 기록(재현성).

> 구현: [`supabase/migrations/`](../supabase/migrations/)

## 8. 비용 계획

| 단계 | 인프라 | LLM (일회성/분기) |

Q&A 비용 가드: 핵심 지표는 **LLM 도달률**(전체 질의 중 SQL 카드·캐시로 끝나지 않고 LLM 답변 생성까지 간 비율). 대시보드로 추적하고, 도달률이 높아지면 단가 협상이 아니라 캐시·라우터 튜닝 우선. 참고: Gemini 2.5 Flash 기준 답변 생성 질의당 ~3원, 월 1만 질의 ~$20.

## 10. 중립성·공개 정책

목표 정의: 시비 0건은 불가능. 목표는 **"어떤 비난도 사실로 반박 가능한 상태"**.

### 10.1 판정 중립성

- **블라인딩**: 판정·매칭 프롬프트 입력에서 인물명·정당명을 마스킹하고 공약 내용·추진현황 텍스트만으로 판정. LLM의 사전 인식이 판정에 개입할 경로를 구조적으로 차단 — "편파 판정" 주장에 대한 기술적 반박 근거
- **동일 기준**: 전 지역·전 인물에 같은 프롬프트, 같은 공식, 같은 기준일 적용
- **편향 모니터링**: 분기마다 정당별 verdict 분포와 자가보고 대비 괴리를 집계해 방법론 페이지에 수치 공개. 쏠림 발견 시 은폐가 아니라 공개 + 원인 조사

### 10.2 표현 원칙

- 기본 화면은 지역별 개별 조회. 비교·순위형 콘텐츠("이행률 꼴찌 TOP 5" 류) 지양
- discrepancy 표기는 사실 기술("공개 자료와의 차이")로 한정, "허위"·"거짓" 등 평가어 금지
- Q&A는 정치적 논평 거절(3.4 범위 제한)

### 10.3 절차

- **정정 요청 채널**: 지자체·당사자용 폼/이메일 운영. 처리 원칙 — 근거 재검토 → 판정 변경 시 변경 이력 공개(judgments 누적 구조 활용)
- **운영자 분리**: 서비스 계정·레포(커밋 메시지·이슈·PR 포함)에서 운영자 개인의 정치 성향 표출 금지. 운영자 간 사전 합의 사항
- **선거법 확인**: 평상시 운영은 공개 자료 기반 사실 전달이나, 선거 기간 규제는 별도 영역 → **8월 공개 전 선관위 서면 질의(유권해석) 접수**(질의는 6~7월 중 발송). 답변과 무관하게 "선거 기간 운영 정책"을 방법론 페이지에 명문화

### 10.4 오픈소스 정책 (Apache-2.0)

- **코드 — Apache-2.0**: 운영 부담 최소화를 우선해 AGPL 대신 선택(결정 기록: AGPL의 파생 서비스 소스공개 강제 대신, Apache의 특허 허여 + 상표 불허여 조항으로 견제). 서비스명·로고는 라이선스 범위에서 제외됨을 README에 명시. 변경 공지 의무(4조b)는 git 히스토리로 충족
- **데이터 — CC BY 4.0**: 판정 결과·이행률 데이터셋 공개(언론·연구 활용 = 신뢰 자산). 단 evidence_chunks 원문 재배포는 출처 자료의 공공누리(KOGL) 유형 확인 후 결정(1주차 조사 항목)
- **day-1 public**: 첫 커밋부터 공개 — 개발 이력 전체가 "숨긴 것 없음"의 증거
- **시크릿 위생**: 키는 GitHub Secrets로만 주입, .env는 gitignore + .env.example만 커밋, gitleaks pre-commit 훅. 공공데이터포털 인증키는 약관상 제3자 공유 금지
- **Q&A 프롬프트 공개 전제**: 방어는 프롬프트 비밀이 아니라 구조 — 라우터 사전 필터 + 출력 검증(출처 포함·범위 체크)이 통과해야 노출
- **CONTRIBUTING.md**: 어댑터 작성 가이드(지자체 설정 + 파서 + 테스트 픽스처) 제공 — 미지원 지역 제보를 커뮤니티 PR 파이프라인으로 전환
